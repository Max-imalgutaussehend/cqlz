cql-ai

A from-scratch, 0.6M-parameter Transformer that reads CQL as cqlc lexer tokens, not text, and warns about anti-patterns in your pull requests.

No text tokenizer

Queries go through the cqlc-core lexer. Every token kind has a fixed id, keywords have their own ids, and identifiers become a role token (COL_PK, COL_CK0, COL_SET, …) from the schema, or one of 64 hash buckets. The vocabulary is about 240 ids.

SELECT body FROM events WHERE tenant = ? AND ts > ?
[CLS] SELECT COL_REG FROM TABLE_PK2 WHERE COL_PK = BIND AND COL_CK0 > BIND
The model needs the schema to know which columns are keys. cql-ai check reads CREATE statements from --schema or from the checked files and refuses to run without them.

Training data: 100,000 synthetic statements from a randomised AST-to-text generator over random schemas, labelled automatically by cqlc-core's analyzer. Validation uses schemas the model has never seen.

Honest limits: the model learns what cqlc's analyzer decides deterministically, plus one rule. It is a fast, fuzzy, schema-aware linter for partial queries, not a replacement for cqlc check, and it cannot see data distributions, so real hot-partition detection is out of scope.

Drop it into CI

# .github/workflows/cql-ai.yml
- uses: actions/cache@v4
  with: { path: ~/.cache/cql-ai, key: cql-ai-model-v1 }
- run: curl -fsSL https://github.com/Max-imalgutaussehend/cql-ai/releases/latest/download/cql-ai-x86_64-unknown-linux-gnu.tar.gz | sudo tar -xz -C /usr/local/bin cql-ai
- run: cql-ai check queries/ --schema schema/ --deny-warnings

The model is fetched from Hugging Face once and cached in ~/.cache/cql-ai/; the CLI statically links the pure-Rust CPU backend.
