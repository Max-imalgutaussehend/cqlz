cqlc, schema-first

KillrVideo

The real 3.x schema from KillrVideo/killrvideo-data (Apache-2.0): 14 tables with counters, static columns and clustering orders. The 13 queries were written for this example following the access patterns the schema comments describe. cqlc checks them offline and generates typed Rust; the demo runs every generated function against a live node.

cd examples/killrvideo-cqlc
cqlc check                     # ok: 13 queries checked

cqlx, code-first

IoT sensor telemetry

The "sensor" model from DataStax's data-modeling-by-example, as one Rust struct. Readings are bucketed by day so partitions stay bounded, inserts are typed, and every read is a type-state query: fetch does not exist until both partition keys are set.

#[derive(CqlEntity, DeserializeRow)]
#[cqlx(table_name = "readings", keyspace = "iot")]
struct Reading {
    #[cqlx(partition_key)] sensor_id: String,
    #[cqlx(partition_key)] day: i32,
    #[cqlx(clustering_key(order = "desc"))] ts: i64,
    temperature: f64,
    humidity: f64,
}

Reading::query().sensor_id("sensor-007".into()).day(20_001).limit(3).fetch(&session).await?;

Learned table design on domain workloads

Three workloads modelled after KillrVideo's access patterns and two DataStax data-modeling-by-example domains (sensors, shopping cart and orders). They are hand-modelled workloads, not those projects' datasets. Costs use the synthetic cost model, so compare columns, not absolute numbers.

Workloadnaivegreedyexact B&Blearned policytables
KillrVideo (7 queries)4,4944,4944,4944,4947
Sensors (6 queries)119,541119,54191,90791,9075
Shop and carts (7 queries)28,03229,81426,54026,5406

Sensors: merging the two read patterns that share a partition key saves 23 % over one table per query. Shop: the learned design is 5 % cheaper than naive and 11 % cheaper than greedy, which opens eight tables. KillrVideo: there is nothing to merge, so every method agrees. On the tiny examples/shop.toml of the repository the policy misses a merge the exact solver finds; it was trained on larger workloads and pays off at scale.

cargo install cqlz-gym
cqlz-gym solve examples/gym-workloads/sensors.toml --policy hf
